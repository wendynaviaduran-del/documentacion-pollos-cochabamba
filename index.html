1. Descripción del Sistema e Integración Empresarial

El sistema administra los productos del almacén y procesa el registro de ventas de la empresa simulada Pollos Cochabamba mediante una aplicación web desarrollada en Python (Flask) y SQLite. El objetivo principal es operar de manera interconectada con áreas externas dentro de la organización:

1.1. Integración con Contabilidad y Empleados

  • Requerimiento Enviado: El sistema consulta mediante API la base de datos de Contabilidad/Empleados para identificar al vendedor en turno y generar informes sobre el empleado con mayor volumen de ventas.
  • Requerimiento Recibido: Contabilidad consume la API REST de Ventas para obtener el registro de transacciones e ingresos totales en Bolivianos (Bs) requeridos en sus balances financieros.

1.2. Integración con Marketing

  • Requerimiento Recibido: El área de Marketing se conecta a la API para consultar las existencias del catálogo (pollo, papas, bebidas) y diseñar combos, promociones y campañas publicitarias según el stock disponible.

2. Herramientas y Tecnologías Utilizadas

  • Python: Lenguaje principal en la programación de la lógica de negocio (Backend).
  • Flask: Microframework para la construcción de rutas web y endpoints de la API REST.
  • SQLite 3: Motor de base de datos relacional almacenado localmente en inventario_demo.sqlite3.
  • HTML5 & JavaScript (ES6+): Interfaz de usuario dinámica con peticiones asíncronas (Fetch API).
  • Waitress: Servidor WSGI de grado de producción para la ejecución sobre Windows/Linux en red local.

3. Funcionamiento Interno y Flujo de Trabajo

3.1. Pantallas Web (Frontend)

  • Panel de Inventario (panel.html): Despliega el catálogo con ID, Nombre, Categoría, Stock base y Presentaciones comerciales. Incluye el botón "Actualizar productos" para recargas asíncronas vía GET /api/v1/productos.
  • Formulario de Registro (ventas.html): Captura el vendedor, producto, presentación y cantidad (admitiendo decimales para kilogramos y enteros para unidades). Al enviar, invoca el endpoint POST /api/v1/ventas.
  • Historial de Ventas: Lista las órdenes en estado Pendiente o Pagada, permitiendo acciones de cobro o anulación mediante peticiones PUT.

3.2. Flujo de Procesamiento en Backend

  1. Verificación de existencia, estado activo y fecha de vencimiento del producto.
  2. Conversión de la cantidad solicitada (ej. 1.5 kg) a unidades base internas (1500 g) utilizando el factor_base.
  3. Validación de suficiencia de stock en la base de datos.
  4. Descuento inmediato del stock base y creación de la orden en estado PENDIENTE.
  5. Registro automático de auditoría de entrada/salida en la tabla movimientos.

4. Especificación de Endpoints y Métodos HTTP

4.1. Consultas (Método GET)

Método Ruta / Endpoint Descripción
GET /api/v1/productos Retorna el listado completo de productos activos y sus presentaciones.
GET /api/v1/productos/<id> Obtiene los detalles específicos de un producto por su ID.
GET /api/v1/inventario Consulta el estado global del inventario en almacén.
GET /api/v1/ventas Obtiene el historial de ventas registradas.
GET /api/v1/reportes/ventas-empleados Genera el consolidado de ventas por vendedor (para Contabilidad).

4.2. Registro y Creación (Método POST)

Método Ruta / Endpoint Descripción
POST /api/v1/ventas Registra una nueva venta, descuenta stock y crea movimientos.
POST /api/v1/productos Registra un nuevo producto en la base de datos.
POST /api/v1/inventario/entradas Registra el reabastecimiento de mercancía al almacén.

4.3. Modificación y Desactivación (Métodos PUT / DELETE)

Método Ruta / Endpoint Descripción
PUT /api/v1/ventas/<id>/pagar Cambia el estado de una venta a PAGADA y registra la fecha.
PUT /api/v1/ventas/<id>/anular Anula la venta pendiente y reintegra el stock devuelto.
PUT /api/v1/productos/<id> Modifica datos de un producto (nombre, categoría, vencimiento).
DELETE /api/v1/productos/<id> Desactiva lógicamente un producto (activo = 0).

5. Estructura de la Base de Datos (DDL SQLite)

El esquema está diseñado en SQLite con restricciones de integridad referencial:

CREATE TABLE productos (
    id INTEGER PRIMARY KEY,
    nombre TEXT NOT NULL,
    categoria TEXT NOT NULL,
    unidad_base TEXT NOT NULL CHECK (unidad_base IN ('g', 'unidad')),
    stock_base INTEGER NOT NULL DEFAULT 0 CHECK (stock_base >= 0),
    vence TEXT,
    activo INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE presentaciones (
    id INTEGER PRIMARY KEY,
    producto_id INTEGER NOT NULL REFERENCES productos(id),
    nombre TEXT NOT NULL,
    factor_base INTEGER NOT NULL CHECK (factor_base > 0),
    precio_bs TEXT NOT NULL
);

CREATE TABLE ventas (
    id INTEGER PRIMARY KEY,
    empleado_id TEXT NOT NULL,
    fecha_venta TEXT NOT NULL,
    fecha_pago TEXT,
    estado TEXT NOT NULL,
    monto_total_bs TEXT NOT NULL
);

6. Seguridad e Integridad Aplicada

  1. Consultas SQL Parametrizadas: Uso exclusivo de marcadores de posición (?) para blindar el sistema contra Inyección SQL (SQLi).
  2. Control de Acceso CORS: Implementación de flask_cors para autorizar de forma explícita las llamadas HTTP desde los orígenes de las demás áreas.
  3. Límite de Tamaño de Petición: Restricción del Payload a un máximo de 1MB (MAX_CONTENT_LENGTH = 1024 * 1024) para mitigar ataques DoS.
  4. Precisión Monetaria con Decimal: Sustitución de flotantes por el tipo Decimal de Python con redondeo bancario para prevenir discrepancias en centavos.
  5. Manejo Centralizado de Excepciones: Formateo homogéneo de errores en JSON evitando la exposición de trazados de pila (Stack Traces) al cliente.
